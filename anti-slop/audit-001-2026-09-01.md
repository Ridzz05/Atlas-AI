# Anti-slop audit 001 — Second Brain UI

Tanggal: 1 September 2026  
Scope: halaman `/brain`, khususnya dialog **Add Document to Second Brain**, berdasarkan screenshot pengguna dan pemeriksaan statis `apps/dashboard/src/app/brain/page.tsx` serta `apps/dashboard/src/theme/theme.ts`.

Belum ada kode UI yang diubah. Temuan berikut menunggu persetujuan nomor dari pengguna.

## Temuan

1. **HIGH — Kontras tombol dan badge utama gagal WCAG AA (R-25).** Teks putih pada `#ff4f00` hanya memiliki rasio **3.30:1**, di bawah syarat 4.5:1 untuk teks normal. Kombinasi ini dipakai pada tombol submit dialog, tombol Add Note, badge GLOBAL RAG, chip aktif, dan beberapa status. Gunakan warna utama yang lebih gelap (misalnya token `primary.dark` yang terukur 4.53:1) atau teks gelap yang lolos kontras.

2. **HIGH — Teks sekunder tertentu juga gagal WCAG AA (R-25).** `#8c827a` hanya mencapai **3.76:1** di atas putih dan **3.54:1** di atas kanvas `#fbf8f2`. Warna ini dipakai pada caption, path dokumen, empty copy, dan metadata kecil, sehingga ukuran kecil memperburuk keterbacaan. Ganti dengan token sekunder yang minimal 4.5:1.

3. **HIGH — Kegagalan API disamarkan sebagai data kosong/palsu dan loading awal tidak dirender (R-27, R-38, C-4, C-5).** Tiga request awal masing-masing menangkap error dan mengembalikan statistik nol, koleksi kosong, serta model `minimax/minimax-m3:free`. State `loading` ditulis tetapi tidak pernah dipakai pada JSX. Akibatnya layar dapat terlihat sehat seperti pada screenshot walaupun API gagal. Tampilkan loading, error, dan empty state yang berbeda; jangan isi fallback yang tampak seperti data nyata.

4. **HIGH — Submit dialog tidak memiliki state proses dan error yang terlihat di dalam dialog (R-27, R-26, C-4).** `handleIngestNote` tidak memiliki flag pending, tombol tetap aktif selama POST, dan error ditulis ke alert halaman yang tertutup backdrop dialog. Pengguna bisa mengirim berulang dan tidak melihat alasan kegagalan. Tambahkan pending state, disable action/cancel sesuai kebutuhan, progress text, dan error inline yang diumumkan dengan `role="alert"`.

5. **HIGH — Dua tombol ikon tidak memiliki accessible name (R-32, R-26).** Tombol kirim chat hanya berisi ikon `Send`, dan tombol hapus dokumen hanya berisi `Trash2`; keduanya tidak memiliki `aria-label`. Screen reader akan menemukan tombol tanpa nama. Tambahkan label kontekstual, misalnya `Send message` dan `Delete {title}`.

6. **HIGH — Footer dialog tidak dirancang ulang untuk viewport sempit (R-03, R-35).** `DialogActions` selalu satu baris dengan padding besar dan CTA panjang “Ingest & Embed Note”. Pada lebar 320 px, ruang isi dialog tidak cukup untuk dua tombol tanpa menjadi sesak atau meluber. Buat actions bertumpuk/full-width pada breakpoint kecil, lalu verifikasi pada 320, 768, 1024, dan 1440 px.

7. **MEDIUM — Bahasa dialog tidak konsisten dan terlalu teknis untuk aksi utama (R-31, C-1).** Judul memakai “Document”, field memakai “Note”, dan CTA memakai “Ingest & Embed Note”. Pengguna harus menerjemahkan tiga istilah untuk satu objek, sementara detail embedding bukan keputusan pengguna. Pilih satu istilah dan gunakan CTA berbasis hasil, misalnya “Add note”; jelaskan indexing sebagai helper/status.

8. **MEDIUM — Oranye dipakai untuk terlalu banyak peran sehingga hierarki fokus melemah (R-01, R-31).** Warna yang sama muncul pada CTA, ikon, badge, tab indicator, chip filter, border hover, dan border dialog. Pada screenshot hampir semua sinyal bersaing sebagai aksen. Pertahankan oranye untuk satu momen utama per area dan gunakan warna netral/semantik untuk status atau dekorasi lain.

9. **MEDIUM — Tipografi “AI dashboard” dipakai tanpa arah merek tertulis (R-06).** Label monospace/uppercase berukuran sangat kecil (`0.65rem`–`0.75rem`) tersebar di metrics dan badge, sementara proyek tidak memiliki `DESIGN.md`. Ini mengurangi keterbacaan dan membuat identitas bergantung pada pola dashboard generik. Tetapkan alasan tipografi, naikkan ukuran label kritis, dan batasi monospace pada data yang memang bersifat kode/path.

10. **LOW — Struktur halaman mengikuti shell dashboard generik dan mengalahkan tugas utama layar (R-20, C-3).** Sidebar, top bar, empat metric card setara, tabs, lalu area kerja membuat aksi inti “mencari/menambahkan pengetahuan” turun prioritas. Evaluasi kembali metrik mana yang benar-benar membantu keputusan pengguna dan pindahkan sisanya menjadi informasi sekunder.

## Urutan perbaikan yang disarankan

Mulai dari **1–6** karena merupakan hard gate aksesibilitas, state, dan responsivitas. Lanjutkan **7–9** untuk merapikan bahasa dan identitas; **10** dapat dikerjakan sebagai penyempurnaan struktur halaman yang lebih luas.
